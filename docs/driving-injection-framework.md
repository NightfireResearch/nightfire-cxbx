# Injecting C++ into the driving engine

A design for making the driving engine as easy to replace a function at a time as the action engine is.
Written September 2026. Step 1 is done (below); the rest is proposed.

## Where things stand

The action engine's workflow is a comment tag. `// AUTOINJECT` above a function definition, and
`tools/preprocess.py` looks the name up in `tools/functions_action.json` (exported from Ghidra by
`ghidra/NightfireSync.py`) and writes a `WriteJmpTo(address, &function)` into
`src/action/autogenerated_injections.inc`. `// AUTOGEN` above a declaration generates a body that calls the
original, for a replacement that needs something not yet reimplemented. `FUNC_AT(address)` names the address
outright. Functions whose arguments arrive in registers (link-time code generation, "custom variable storage"
in Ghidra's terms) are refused unless tagged `AUTOLTCG`, which is the author's promise to have written the
assembly adaptor. It works because the action engine is C: names are unique, and the calling conventions are
the three the compiler knows.

The driving engine is C++, and the same machinery has been used on it exactly once: `UFileLoader`, chosen
because its methods are static and the class has no data. Everything else replaced so far - the scheduler,
the event manager, the startup, the seams - is patched by hand in `src/inject_driving.cpp` or in the seam
code, with the calling convention and the layout checked by reading, if at all.

### The bug that shows why

`AUTOINJECT` matches by name. Ghidra has two functions called `UFileLoader::FileLoad`: `0x00117610`, which
takes `(path, flags, bool)`, and `0x001176b0`, a two-argument overload whose whole body is
`return FileLoad(path, flags, true)`. The one tagged definition was patched over both. Callers of the
two-argument version push two arguments, and the replacement read a third `bool` from whatever lay next on
their stack. It did not corrupt the stack only because both originals are `__cdecl` - measured from the
binary; Ghidra labels them `__stdcall`, and a `__stdcall` mismatch would have popped eight bytes the caller
still owned. There are 22 duplicated names in `functions_driving.json`, so this was going to happen again.

## Why the driving engine is harder

1. **Names are not unique.** Overloads, and the same method name in different classes, which Ghidra
   distinguishes only by namespace (`Class::Method`), and not at all for overloads.
2. **Ghidra's calling conventions cannot be trusted.** 7453 of 7982 driving functions are `unknown`, and the
   labelled ones can be wrong, as `FileLoad` shows. The binary itself says what matters: how many bytes each
   `RET` pops, and whether `ECX` or `EDX` is read before it is written - which is what a register argument,
   `this` included, looks like from inside.
3. **Member functions need layout-compatible classes.** A `__thiscall` replacement works only if
   `this->field` in our class lands on the game's offset. MSVC 7, which built the XBE, and today's MSVC agree
   on the x86 `__thiscall` ABI (`this` in `ECX`, the callee pops the rest), so a non-virtual member function of
   a class with the same layout is a drop-in replacement. The layout is the hard part.
4. **C++ hides addresses.** A constructor's address cannot be taken. The address of a virtual method is a
   compiler-generated thunk that dispatches through the vtable, not the method. A pointer to a member of a
   class that is incomplete where the pointer type is formed is 16 bytes under MSVC's default, not 4.

## The framework

The central idea: **the compiler checks the C++ declarations against facts measured from the binary.** The
preprocessor emits the checks; it never has to understand C++ well enough to check anything itself.

### 1. ABI facts, measured

A new `tools/abi_facts.py` disassembles every function in the XBE (capstone, as
`tools/xbe_entry_points.py` already does for the library entry points) and records, per function:

- the bytes popped by its `RET` - 0 for `__cdecl`, the argument size for `__stdcall` and `__thiscall`;
- whether `ECX` and `EDX` are read before they are written - `this`, or a `__fastcall` argument;
- the first eight bytes, for the install-time check in section 7.

The output is committed (`tools/abi_driving.json`, and the same for the action engine) because CI builds
without the disc, as `functions_*.json` is.

### 2. Compile-time checks in the generated table

Type traits over function-pointer and member-function-pointer types can compute what a declaration implies:
how many bytes the callee pops, and whether `this` comes in `ECX`. The generated injection table then
carries the measured facts beside each patch:

```cpp
XBE_PATCH(0x00117610, "UFileLoader::FileLoad",
          XbeOverload<void *(char *, int, bool)>::Of(&UFileLoader::FileLoad),
          /*pops*/ 0, /*ecx*/ false);
// expands to a static_assert on Abi<decltype(...)>::calleePops and ::thisInEcx, then the WriteJmpTo
```

Declare a method `static` when the original was `__thiscall`, or forget `__stdcall`, and the build fails
naming the function. The D3D8 seam does this at install time (`src/common/xbeEntrySeam.cpp` compares each
replacement's declared pops against the generated table), and it found two wrong ones on its first run;
this moves the same check to compile time and extends it to every tagged function.

### 3. Matching that knows about overloads

The preprocessor matches a tag on the name and the number of parameters, which it can count from the
tagged line, and refuses anything still ambiguous: "add `FUNC_AT(address)`". When our own code defines more
than one function of a name, the generated table selects the right one with a cast built from the tagged
signature (`XbeOverload<Signature>::Of`, which works for free functions, static members and member functions
alike). **Done - this is step 1.**

### 4. Overlay classes for the game's data

A C++ class that stands in for one of the game's follows these rules:

- **The exact layout, field by field**, with `static_assert(sizeof(...))` and `offsetof` checks.
  `src/driving/Scheduler.hpp` already does the `sizeof` half by hand. Generated from Ghidra's struct
  definitions once `NightfireSync.py` exports them - `preprocess.py` already has that as a TODO.
- **No `virtual` keyword.** A class with a vtable declares `void **vtable;` as its first member explicitly;
  the compiler must never add a vtable pointer of its own. Replacing a virtual method is patching the
  function the vtable points at, like any other; calling one from our code goes through a small
  `VCall<R>(object, slot, args...)` helper, with the slot numbers generated from Ghidra's vtables.
- **Never constructed by our code.** Instances are always the game's; `this` is reinterpreted. Objects are
  created by calling the game's own constructors.
- **`__single_inheritance`** on the forward declaration, so that member-function pointers are 4 bytes
  wherever they are formed.
- **Constructors and destructors** are ordinary methods (`Construct()`, `Destruct()`) tagged with
  `FUNC_AT`, since the language will not give their addresses.

### 5. `AUTOGEN` from our declaration, not Ghidra's types

Today `AUTOGEN` generates a caller from Ghidra's types, which for the driving engine are mostly `undefined4`
and `unknown`, and it cannot produce a member function at all. Instead, the author writes the declaration -
in the class, where it belongs - and the preprocessor generates only the body:

```cpp
class UFileLoader {
    // AUTOGEN
    static void *AttemptBigFileLoad(char *path, int flags);
};

// generated
void *UFileLoader::AttemptBigFileLoad(char *a0, int a1) {
    return XbeOriginal<decltype(XbeOverload<void *(char *, int)>::Of(&UFileLoader::AttemptBigFileLoad))>(0x00117530)(a0, a1);
}
```

For a non-static method the body is `(this->*XbeOriginal<...>(address))(a0, ...)` - MSVC will not put
`__thiscall` on a free function pointer, so the member-pointer form is used, with the `__fastcall(ecx,
edx_unused, ...)` trick as the fallback. The traits of section 2 check these declarations too. This needs the
preprocessor to scan headers as well as `.cpp` files.

### 6. Register-argument adaptors, generated

Ghidra's export already records where each parameter lives (`param_1@EAX`, `this@ECX`, `@Stack[0x4]`).
From that the preprocessor can emit the naked-assembly adaptor that `AUTOLTCG` currently asks a person to
write: move the register arguments to where a normal convention wants them, call the C++ function, put the
result back. That covers the driving engine's 55 functions with custom storage and closes the action
engine's `AUTOLTCG` TODO.

### 7. Runtime safety nets

- **Checked patch sites.** The generated table carries each original's first bytes (section 1), and
  install compares them before patching, as `src/driving/platform/XboxTimer.cpp`'s `PatchSite` does. A stale
  `functions_*.json`, a different build of the XBE, or a wrong `FUNC_AT` is reported by name rather than
  written into the middle of an instruction.
- **`AUTOINJECT(standalone)`**, for patches that must not apply under CXBX - the reason the startup
  replacements in `XboxStartup.cpp` are patched by hand today.
- **Named replacements in crash reports.** The table of what has been replaced, so that `crash.log` can say
  "inside the replacement for `UFileLoader::FileLoad`" rather than an address in `drivinginject.dll`.

## Order of work

1. **Overloads and ambiguity** (section 3), and the `FileLoad` fix. *Done, 25 September 2026.*
2. **ABI facts and the compile-time checks** (sections 1 and 2) for the tags that exist, then moving the
   hand-written patches in `inject_driving.cpp` (`Scheduler::Run`, the event manager) onto tags so they are
   checked too. Together with step 1, this makes the driving engine's `AUTOINJECT` as safe as the action
   engine's.
3. **Overlay classes and declaration-driven `AUTOGEN`** (sections 4 and 5), proved on `Scheduler`, whose
   layout and `Run` are already written. This is the step that makes classes with data ergonomic.
4. **Struct export from Ghidra** for the layout checks, and the **register-argument adaptors** (section 6)
   when a function needs one.
5. **The runtime safety nets** (section 7) alongside whichever of the above touches the table next.

## Step 1, as done

- `tools/preprocess.py` matches `AUTOINJECT`/`AUTOLTCG` tags on name and parameter count, and fails with a
  message naming the candidate addresses when that leaves more than one - or when a name matches several
  functions and the tag's parameter count matches none. `FUNC_AT` remains the way to say which.
- When two tagged definitions share a name, the generated `WriteJmpTo` selects each through
  `XbeOverload<Signature>::Of` (`src/common/xbeOverload.h`), with the signature taken from the tagged line.
- The two-argument `UFileLoader::FileLoad` is implemented - `FileLoad(path, flags, true)`, as the original -
  and patched over `0x001176b0`; the three-argument replacement is patched only over `0x00117610`.
- The bug was live, not only latent. Loading the underwater level before and after, the same 97 files load,
  and two of them - `data\loading\uw_mis11.ini` and `data\render\camera.ini`, the ones that come through the
  two-argument overload - were being loaded with `false` for the argument the original passes as `true`. They
  now load as the original loads them. The action engine's generated table is unchanged, patch for patch.
